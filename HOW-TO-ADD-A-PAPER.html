How to Add a Paper

The pipeline that turns a question-paper PDF into a fully solved page on this site

Repeatable · one paper at a time

The short version

  1. Commit the question-paper PDF into papers-inbox/ in this repository.
  2. Ask for it to be solved, naming the file.
  3. Each question is transcribed into MathJax and worked out; the paper's JSON file in data/papers/ fills up batch by batch.
  4. python3 tools/build.py regenerates the paper page and the papers index.
  5. The commit is pushed and GitHub Pages publishes it.
Why the PDF must be committed rather than shared as a link. Cloud-drive links cannot be opened from the build environment — outbound access to drive.google.com is blocked by policy. A file inside the repository is read directly from disk, which also means the exact source of every solution stays archived next to the solution itself.

Repository layout

PathWhat lives there
papers-inbox/Raw question-paper PDFs waiting to be processed, exactly as downloaded.
data/papers/*.jsonOne file per paper: metadata plus every question, its options, its answer and its worked steps. This is the only place content is edited.
tools/build.pyGenerator. Reads the JSON, writes the HTML. Never edit a paper's HTML by hand — the next build overwrites it.
papers/*.htmlGenerated output: one page per paper, plus the papers index.
assets/styles.cssShared stylesheet for the whole site.

The shape of a question in the JSON

Each entry in the questions array carries the question and its solution. Anything written in body, options, steps and the rest is HTML with inline MathJax, so $\int_0^1 x^2\,dx$ renders as mathematics.

{
  "n": 27,
  "qid": "706507",
  "part": "B",
  "topic": "Linear Algebra",
  "subtopic": "Eigenvalues",
  "type": "single",
  "body": "Let $A$ be a $3\times 3$ real matrix with $A^2 = A$ and $\operatorname{rank}(A)=2$. Then the characteristic polynomial of $A$ is:",
  "options": ["$x^3 - x^2$", "$x^3 - 2x^2 + x$", "$x(x-1)^2$", "$(x-1)^3$"],
  "answer": [3],
  "given": "$A$ is idempotent, real, of size $3$, with rank $2$.",
  "concept": "An idempotent matrix is diagonalisable with eigenvalues only $0$ and $1$; the multiplicity of the eigenvalue $1$ equals the rank.",
  "steps": [
    "<b>Eigenvalues.</b> From $A^2=A$, every eigenvalue satisfies $\lambda^2=\lambda$, so $\lambda\in\{0,1\}$.",
    "<b>Multiplicities.</b> $A$ is diagonalisable, so the multiplicity of $1$ is $\operatorname{rank}(A)=2$ and that of $0$ is $3-2=1$.",
    "<b>Characteristic polynomial.</b> Hence $\chi_A(x)=x(x-1)^2$."
  ],
  "conclusion": "Option (3) is correct.",
  "pitfall": "Rank fixes the multiplicity of $1$, not of $0$. Reading it the other way gives option (2)."
}
Field notes
  • answer is a list of 1-based option numbers. Part C questions may hold several, for example [1, 3, 4].
  • type is "single" for Parts A and B, "multiple" for Part C.
  • topic feeds both the topic filter and the distribution chart, so keep the names consistent across papers.
  • A question with an empty body or an empty answer is treated as not yet done and is simply left out of the published page. That is what lets a paper go up in instalments without ever showing a blank question.

Rebuilding

python3 tools/build.py

It prints one line per paper with the number of questions solved out of the total, then rewrites papers/index.html. There are no dependencies beyond the Python standard library, and nothing to install.

The progress bar at the top of each paper page and the status pill on the papers index are both computed from the JSON, so they can never disagree with what is actually published.

Starting a brand-new paper

Copy an existing file in data/papers/, change slug, title, short_title, exam_date, shift and blurb, then empty out the question bodies. The slug becomes the page's file name and its permanent URL, so use the pattern YYYY-MM-DD-subject-shiftN and do not change it afterwards.

The parts array describes the paper's structure. For CSIR NET Mathematical Sciences it is always Part A questions 1–20, Part B 21–60 and Part C 61–120, but the field exists so that a differently structured paper can be added without touching the generator.
